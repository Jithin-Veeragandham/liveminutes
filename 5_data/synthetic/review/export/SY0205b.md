## Gold: summary (F1)

**abstract**
- The project manager opened the functional design meeting and noted that the user interface designer was absent because he was at a conference. She reported that the minutes and brief had been circulated but the operator's brand guide had not yet arrived. The marketing expert presented user requirements for commuters and tourists and her competitor app review, and reported that the operator allows a no-account guest day pass with a card pre-authorisation. The industrial designer reported that all four hundred docks have QR codes, ninety older docks have only keypads and the rest have Bluetooth, and none support NFC. The team agreed on QR scanning as the main unlock method with a one-time keypad code as fallback, and on map pins showing numbers and shapes with colour only as a secondary cue. The project manager summarised the agreed functions and assigned follow-up work, including a map screen mock-up for the absent user interface designer.

**actions**
- The marketing expert will send her competitor review screenshots and findings to the user interface designer.
- The user interface designer will produce a first version of the map screen with numbered and shaped pins, based on the competitor findings.
- The user interface designer's list of technical functions is carried over to the next meeting.
- The industrial designer will work out the full unlock flow step by step, including screens and server calls, to check it fits within thirty seconds.
- The industrial designer will check the timing of the one-time keypad code with the operator contact.
- The marketing expert will find out from visitor statistics whether tourists need languages beyond English, German and French.
- The project manager will chase the operator's brand guide again.
- The project manager will send the user interface designer the minutes and his tasks, and check that he has time for them.
- Checking what the operator's live data feed costs was raised, but nobody took it on.

**decisions**
- Tourists can buy a guest day pass without a full account, secured by a card pre-authorisation of about 150 euros.
- Map pins will show the number of bikes and a shape (full circle, half circle or empty ring), with colour only as a secondary cue.
- QR code scanning is the main unlock method because it works on every dock.
- A one-time five-digit keypad code shown in the app is the fallback unlock method.
- NFC is ruled out because no docks support it.
- The agreed functions are the live availability map as main screen, favourite home and work docks, QR unlock with keypad code fallback, a guest day pass, and English, German and French language support.

**problems**
- The operator's brand guide has not been received, and pin colours depend on it.
- It is unknown whether the operator charges for its live availability data feed, which could affect the 120,000 euro budget, and nobody took on checking it.
- The user interface designer's technical functions list is not yet finished.
- There is concern about whether the user interface designer has enough time, given his workload.
- The marketing expert's idea of notifications when a favourite dock runs low on bikes was left open pending the user interface designer's view.
- The thirty-second unlock target depends on the number of screens before scanning, which is still to be worked out.
